# 项目的架构与主要功能

## 架构（两半）

| | Host | Client |
|--|------|--------|
| 源码 | `src/index.ts` | `src/client/` |
| 产物 | `dist/index.js`（tsc） | `dist/client.js`（esbuild） |
| 职责 | 文件系统 RPC + 根目录固定 | 文件树 UI + Monaco 编辑器 |

包名：`@rose43/dsh-file`。浏览器不直接碰磁盘，一律走 Typert `fileManager` RPC；路径经 `resolveInside` 校验，防越界 / symlink 逃逸。

工作区：打开文件管理器时按当前会话 `SessionHeader.cwd` 调用 `setRoot`；无会话时回退 `config.root`（默认 `process.cwd()`）。

## 主要功能

- **侧边栏文件树**：底部「文件」切换；浏览当前对话工作区
- **中间列编辑器**：`conversation.view`「文件」标签；Monaco 语法高亮（CDN 失败则降级 textarea）
- **Markdown**：`.md` 默认预览，可切源码；模式记 localStorage
- **主题**：预设 / 自定义配色，导入导出 JSON（兼容部分 VS Code colors）
- **编辑保存**：Ctrl+S、dirty 标记、多标签
- **文件 CRUD**：新建文件/目录、重命名、删除（非空目录拒绝）
- **可选**：`openLinksInEditor` 把对话里的文件链接路由到本编辑器

## dsh 前端插件体系

### dsh 默认前端是什么

dsh（DeepSeek Harness）Web 的前端是 `@deepseek-ai/dsh-client-web`——一个跑在浏览器里的 Cordis 插件宿主。它本身不包含具体业务 UI，而是提供一个**平台层**，由若干内置（默认）前端插件填充：

- **Cordis 框架**（`@deepseek-ai/cordis`）：插件运行时，核心是 `ctx.slots`（UI 插槽）、`ctx.remote`（RPC）、`ctx.locale`（i18n）、`ctx.effect`（生命周期）。插件通过 `inject` 声明依赖、`slots.register` 注册 UI。
- **Slots（插槽）系统**：预定义的 UI 扩展点，如 `sidebar.workspaces`（侧边栏主区域，默认被工作区浏览器以 priority 0 占用）、`conversation.view`（中间列会话视图标签，默认有「对话/轨迹」）、`sidebar.footer.action`（侧边栏底部操作按钮）、`settings.plugin.item`（设置页插件卡片）。单席位 slot 渲染 priority 最低的存活条目。
- **Typert Remote 协议**（`@deepseek-ai/dsh-typert-protocol`）：浏览器↔Node 进程的 RPC。Host 用 `@Remote()` 装饰器暴露端点，Client 用 `ctx.remote.$mount()` 挂载调用面（`ctx.get('remote.<namespace>')` 解析）。
- **ModuleLoader**：浏览器侧模块加载器（`window.__ModuleLoader__.load({ id, factory })`）。平台把 react、cordis、dsh-client-ui-* 等「seed 词」预置在模块表里，插件 bundle 只需把这些声明为 external。
- **dsh-client-modules**：host 启动时扫描已注册 loader 条目中 `package.json` 声明了 `dsh.client` + `exports["./client"]` 的包，自动把 `dist/client.js` 挂到 `/plugins/<包名>/client.js` 并写入 `window.__DSH_BOOT__`，浏览器据此引导加载。

简言之：dsh 前端 = Cordis 平台 + 一组默认插件（工作区浏览器、对话视图、设置页等），第三方插件以同样的机制往 slots 里注入 UI。

### 本插件如何更新 dsh 前端插件的 WebUI

dsh-file 作为一个**第三方插件**，通过以下全链路更新 / 扩展 dsh 前端的 WebUI：

**1. 注册入口（`cordis.patch.yml` + `package.json`）**

`dsh plugin --profile web add .` 把包链入 profile 并追加到 `dsh.profile.bundles`。`cordis.patch.yml` 声明一条 loader 行（`id: @rose43/dsh-file`），host 据此加载 `dist/index.js`（默认导出 = `FileManagerGateway`，即 Typert Remote 服务）。`package.json` 的 `dsh.client.platform: web` + `exports["./client"]` 让 `dsh-client-modules` 自动发现并服务 client bundle。

**2. 构建两半（`build.mjs`）**

| 半 | 源码 | 产物 | 工具 | 关键约束 |
|----|------|------|------|---------|
| Host | `src/index.ts` | `dist/index.js` | tsc | 必须用 tsc：`@Remote()` 是 stage-3 装饰器，esbuild 会降级为 legacy 形式导致运行时崩溃 |
| Client | `src/client/index.tsx` | `dist/client.js` | esbuild | 打成 `window.__ModuleLoader__.load({id, factory})` 格式；react 等 seed 词 external；CSS 以 text 内联 |

**3. Client 注册 UI（`src/client/index.tsx`）**

插件 `inject: ['slots', 'locale', 'remote', 'settingsScope']`，启动后通过 Cordis slots 把自身注入 dsh 前端的各个 UI 插槽：

| Slot | 注入内容 | 机制 |
|------|---------|------|
| `sidebar.footer.action` | 底部「文件」按钮 | `slots.register`，点击 toggle 面板 |
| `sidebar.workspaces` | 文件树面板 | 以 priority -1 注册 shadow 条目（默认工作区浏览器 priority 0 → 本插件赢得单席位）；关闭时注销，工作区浏览器自动恢复 |
| `conversation.view` | 中间列「文件」编辑器标签 | `slots.inject` + `slots.register`，点击文件后在会话滚动区渲染（非弹窗） |
| `settings.plugin.item` | 设置卡片 | `slots.inject` + `slots.register`，key = `dsh-file` 命名空间 |

同时 `ctx.remote.$mount(TYPERT_REMOTE)` 把 host 的 `fileManager` RPC 端点挂到 `ctx.remote.fileManager`，UI 组件直接调用。

**4. 更新 WebUI 的流程（改了代码后）**

- **Host 半改动**：`node build.mjs` 重构建 → 重启 `dsh web`（host 进程内加载，必须重启）。
- **Client 半改动**：`node build.mjs`（或 `--watch`）重构建 → **刷新浏览器页面**即可（bundle rev 变化触发 ModuleLoader 重新加载，无需重启 dsh）。
- **插件元数据改动**（`package.json` 的 `dsh.client` 等）：需重启 `dsh web`（client 元数据按名缓存，重启后重新扫描）。

> 总览：dsh-file 不替换 dsh 前端，而是以**同等的 Cordis 插件身份**，通过 slots 注入 + Typert Remote RPC 两层机制，把自己的文件树 / 编辑器 / 设置卡片「嫁接」到 dsh 前端的既定位置——对平台而言它与默认插件无异。
